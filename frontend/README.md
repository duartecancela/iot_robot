# Frontend – IoT Robot Web Interface

Web-based frontend for the IoT Robot Platform.

This application provides a real-time interface to visualize robot telemetry,
control movement, manage **tracking behavior**, visualize the live camera stream,
and control MongoDB logging.

It communicates with the backend using:
- **HTTP (REST)** → aggregated state + commands
- **Socket.IO** → real-time updates

---

## Tech Stack

- React
- Vite
- Tailwind CSS
- Socket.IO client
- Heroicons (`@heroicons/react`)

---

## Features

- Real-time telemetry dashboard
- Differential drive joystick control
- Drive ACK visualization
- **Tracking state visualization (NEW)**
- **Tracking enable/disable control (NEW)**
- **Live MJPEG camera stream (NEW)**
- **MongoDB logging control (NEW)**
- Responsive UI with Tailwind CSS

## Architecture Overview

```text
Frontend (React)
   ↓ HTTP / Socket.IO
Backend (Node.js)
   ↓ MQTT
Broker
   ↓ MQTT
ESP32 Robot
```

- Frontend does NOT talk MQTT directly
- Backend is the only integration layer

## Telemetry Dashboard

The `TelemetryState` component displays:

### Sensors
- ToF (front-left / front-right)
- IMU (pitch, roll)
- BME280 (temperature, humidity, pressure)

### Drive
- Applied motor values
- ACK status

### Tracking (NEW)

| Field | Description |
|------|------------|
| `Moving` | Robot is currently moving |
| `Tracking Active` | Tracking system is running |
| `Tracking Allowed` | Manual enable/disable state |

---

## Tracking Control (NEW)

The frontend allows enabling/disabling tracking via:

```text
POST /tracking
```

### Payload

```json
{
  "tracking_allowed": true
}
```

### Behavior

- Sends command to backend
- Backend publishes:
  ```
  robot/tracking/command
  ```
- Backend updates tracking state
- UI reflects new state automatically

---

## Tracking Logic

Tracking is manually controlled from the frontend.

### Behavior

- Frontend sends:
  ```text
  POST /tracking
  ```
- Backend publishes:
  ```text
  robot/tracking/command
  ```
- Raspberry Pi tracking controller reacts to:
  ```text
  tracking_allowed
  ```

The frontend only controls and visualizes the state.

## Camera Stream

The frontend supports live MJPEG video streaming.

### Stream endpoint

```text
http://<raspberrypi>:8080/stream.mjpg
```

### Environment variable

```env
VITE_STREAM_URL=http://192.168.x.x:8080/stream.mjpg
```

### Notes

The stream is generated by:

```bash
TARGET=bird python -m camera.camera_stream
```


### Features

## Drive Joystick

### Behavior

- `x` → turning
- `y` → forward/backward

```text
left  = y + x
right = y - x
```

- Range: `-255 .. 255`
- Sends updates ~20 Hz
- Auto stop on release

## Backend Communication

### HTTP (Polling)

```text
GET /telemetry/state
```

Used for:
- dashboard data
- tracking state
- initial load

---

### HTTP (Command)

```text
POST /tracking
```

Used for:
- enabling/disabling tracking

---

### Socket.IO (Real-time)

#### Incoming events

| Event | Description |
|------|------------|
| `telemetry:fast` | Fast telemetry |
| `telemetry:slow` | Slow telemetry |
| `drive:state` | Drive state |
| `drive:ack` | ACK |
| `tracking:status` | Tracking updates (NEW) |

#### Outgoing events

| Event | Payload |
|------|--------|
| `cmd:drive` | `{ left, right }` |

## Network Access

To allow access from other devices:

```js
server: {
  host: true,
  allowedHosts: 'all'
}
```

During development, using the Raspberry Pi IP address may be more reliable:

```text
http://192.168.x.x:5173
```

Some browsers may block:
- MJPEG streams
- WebSockets
- local network requests

when using `.local` hostnames.

## Troubleshooting

- Blank page:
  ```bash
  npm install
  ```

- Backend not reachable:
  - Check `VITE_BACKEND_URL`

- No telemetry:
  - Confirm backend + MQTT running

- No camera stream:
  - Confirm camera stream is running on port `8080`
  - Check `VITE_STREAM_URL`
  - Try accessing the stream directly in the browser
